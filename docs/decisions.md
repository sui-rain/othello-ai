# 決めたことと理由

## 当初の決定
| # | 決めたこと | 理由 |
|---|---|---|
| D1 | 改善の判定を「正しさ」「答え一致＋速度」「強さ（SPRT）」の段階に分ける | 勝敗だけだと運に左右され、一晩で白黒がつかない。答えが変わらない変更は運なしで判定できる |
| D2 | 判定に使うものは保護対象にし、夜間のAIは変更禁止 | テストを緩めて「改善した」ことにする抜け道を防ぐ |
| D5 | 対局の序盤は、偏りの少ない8手目の局面集（重複除去済み、`bench/` に保存）から先後入れ替えで開始 | 同じ展開ばかりになるのを防ぎ、先手有利の偏りを打ち消す |
| D6 | 夜間の定期実行は0:40（日本時間）、一晩1件から開始 | 21:30開始の5時間枠の残りを使う。枠の消費量を1週間見てから増やす |
| D8 | `main` への直接pushは禁止。取り込みは判定合格したプルリクエストのみ | 壊れた変更が最強版を上書きしないようにする |
| D9 | 評価関数は手書き → パターン学習 → 量子化ネットワークの順 | 計算量削減を主軸にする方針。学習は判定システムが整ってから |
| D10 | グラフページはGitHub Pages（静的） | 更新にAIを使わないので枠を消費しない |

## 別AIレビュー（2026-10-21）を受けた決定
指摘15件はすべて反映した。

| # | 指摘 | 対応 |
|---|---|---|
| R1 | AIが判定を自分で無効化できる | 反映：判定は保護対象を `main` から取り出して実行。`main` の保護ルール。`auto/` ブランチで保護対象（`.github/` などを含む）に触れたらCI失敗 |
| R2 | AIが取り込みを判断し、CIを待つと枠を浪費する（旧D7） | 反映：旧D7を廃止。AIは自動取り込みを予約して終了し、必須チェックの合格でGitHubが取り込む。報告は別に行う |
| R3 | 公開リポジトリの危険（フォーク、指示の混入、秘密情報） | 反映：`pull_request_target` 不使用、判定ジョブは読み取りのみ・秘密なし・時間制限つき。外部の文章を指示として扱わない |
| R4 | どの判定を使うかを誰が決めるか | 反映：CIが「答えが一致したか」で自動で振り分ける |
| R5 | 「最善手と評価値の完全一致」では正当な改善も落ちる | 反映：ルートの評価値で比較し、同値の別の手は再探索で確認。判定モードは1スレッド・局面ごとに置換表初期化・整数評価 |
| R6 | 旧D4のSPRT設定ではほぼ全部が保留になる | 反映：elo0=0 / elo1=10、ペア集計、固定ノード数か短い持ち時間、上限8000局 |
| R7 | 実時間での速度判定（旧D3）はブレに弱い | 反映：旧D3を廃止。命令数（callgrind）を主指標にし、1%以上の削減で合格 |
| R8 | 固定の公開局面だけだと過学習・答えの埋め込みができる | 反映：実行ごとに新しい局面を生成して比較し、固定局面も多様にする |
| R9 | 正しさの検査が合法手生成だけ | 反映：αβ＝ミニマックスの照合、FFO #40〜#49 を全プルリクエストの必須検査にする |
| R10 | 履歴を誰が書くか未定 | 反映：報告用ワークフローだけが `data` ブランチへ書く。判定結果は検証してから使う |
| R11 | 同じ晩の複数プルリクエストが古い基準で判定される | 反映：ブランチ最新化を必須にし、合格版にタグ。週1回、4週間前の版と対戦 |
| R12 | 依存クレートやビルド時コードの混入 | 反映：依存は許可リスト制、`Cargo.lock` をコミット |
| R13 | 実行時間と枠の見積もり | 反映：SPRTは1ジョブ内4並列・最大300分。夜間実行が動かなかった日も報告 |
| R14 | 実行の重複と暴走 | 反映：全ジョブに `timeout-minutes` と `concurrency` を設定 |
| R15 | Edaxの扱い | 反映：版を固定し、取得時にチェックサムを確認。バイナリはリポジトリに入れない |
| R16 | perftの数え方と深さ | 反映：「パスは1手、途中で終局した枝は0」と明記し、深さ10・11まで検査 |

## 実装中の決定
| # | 決めたこと | 理由 |
|---|---|---|
| I1 | マスの番号は「行×8＋列」（A1=0、H8=63）、黒が先手 | 一般的な表記と合わせ、他エンジンの局面と照合しやすくする |
| I2 | 盤面は「手番側の石」と「相手の石」の2つで持つ | 手番によらず同じコードで処理でき、探索が単純になる |
| I3 | 保護対象の変更検出は `auto/` で始まるブランチにだけ適用 | 持ち主や監督つきの作業では判定の仕組み自体を直す必要があるため。夜間のAIは必ず `auto/` を使う |
