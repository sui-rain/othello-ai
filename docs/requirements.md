# othello-ai 要件定義書

## 1. 目的と需要（持ち主の言葉より）
- 標準ルールのオセロで、AI同士の対戦における最強を目指す（実現は難しいと承知のうえで、目安として）。
- 単なる強化学習ではなく、計算量削減（最適化）を主軸に強くする。
- 持ち主が画面を見ていない夜間に、AIが無人で改善を進める。判定は勝敗だけに頼らない。
- 朝に結果を通知で受け取り、速度・勝率・終盤ベンチの推移をグラフで見られるようにする。
- 言語はRust。リポジトリは公開。スマホで遊べる画面は後回し。
- 夜間開発はクラウドで動くClaude（PC不要）が担当。PCを起動している日はCodexにも追加の試行を回せる余地を残す。

## 2. 完成形の機能
### エンジン
- ビットボード（64bit×2）による盤面表現、合法手生成、着手、パス、終局判定
- 探索：反復深化、αβ（ネガスカウト）、手の並べ替え、置換表、時間管理
- 終盤：残り約20マスからの完全読み（勝敗・石差）
- 評価関数：初期は手書き（着手可能数・角・確定石）→ パターン評価の学習 → 量子化した小型ネットワーク
- コマンドライン：局面を受け取り最善手・評価値・読んだ局面数を返す。対戦用の簡単なテキスト通信

### 判定システム（夜間ループの心臓部）
- **正しさ**：perft（深さnの合法手の総数）が既知値と一致
- **速度（答えが変わらない変更用）**：固定局面セットで、変更前と「最善手・評価値が完全一致」かつ「同じ深さまでの時間が縮む」
- **強さ（答えが変わる変更用）**：現行最強版との対戦を逐次確率比検定（SPRT）で判定。決められた序盤局面から先後入れ替えで対局
- **物差し**：FFO終盤テスト（#40〜#59）の解答時間と正答、公開エンジンEdaxとの同条件対戦（週1回）
- 判定用の局面・問題集・採点スクリプトは保護領域に置き、夜間のAIは変更できない

### 夜間ループ
- 0:40（日本時間）にClaudeの定期実行が起動 → 改善候補から1つ選んで実装 → プルリクエスト
- GitHub Actionsが判定を実行 → 合格なら自動で取り込み、不合格・保留なら理由を記録して閉じる
- 結果を `data/history.csv` に1行追記 → GitHub Pagesのグラフページが自動更新
- 朝、スマホに一言の通知（例：「終盤読み 速度+8% を採用」）

### 後回し
- スマホのブラウザで遊べる対戦画面（エンジンをWebAssembly化）

## 3. マイルストーン（各段階で単独で動く状態にする）
| 段階 | 内容 |
|---|---|
| M0 | リポジトリの土台：Cargo、CI（ビルド・テスト・静的検査）、保護領域の変更検出 |
| M1 | 正しく動くエンジン：ビットボード、合法手、perft、ランダム対戦 |
| M2 | 基本の探索：αβ＋反復深化＋手書き評価＋時間管理、CLIで最善手を返す |
| M3 | 判定システム：固定局面セット、一致＋速度判定、対戦ハーネス＋SPRT、FFOベンチ、履歴CSV、グラフページ |
| M4 | 夜間ループの稼働：定期実行、自動取り込みのルール、通知 |
| M5〜 | 改善フェーズ（ループが回す）：手の並べ替え、置換表、ネガスカウト、終盤ソルバー高速化、パターン評価の学習、量子化評価 |
| M6 | 対外比較：Edaxとの週次対戦をグラフに追加 |
| M7 | （後回し）ブラウザ対戦画面 |

M0〜M4は「ループを回せる状態にする」ための土台で、まとめて作る。M5以降は夜間ループが1晩1件ずつ進める。

## 4. 完了条件
- **M0**：`cargo build`・`cargo test`・`cargo clippy -D warnings` がCIで通る。`bench/` か `judge/` に触れるプルリクエストはCIが失敗する
- **M1**：初期局面からのperftが深さ1〜9で既知値（4, 12, 56, 244, 1396, 8200, 55092, 390216, 3005288。OEIS A124004で照合）と一致。ランダム同士の1万局が例外なく終局
- **M2**：深さ固定の探索結果が、αβなしの全探索（ミニマックス）と小さな深さで完全一致。ランダム相手に1000局全勝。1手あたりの時間制限を守る
- **M3**：わざと遅くした変更は速度判定で落ち、わざと答えを変えた変更は一致判定で落ちる（判定システム自体のテスト）。SPRTが既知の強弱差（深さ3対深さ5）を正しく判定。FFO #40〜#59 の正解値と照合できる
- **M4**：手動で起動した夜間実行が、プルリクエスト作成 → 判定 → 取り込み（または却下）→ 履歴追記 → 通知まで一通り完走
- **M5〜**：各改善は判定システムの合格をもって完了とする
- **M6**：Edaxとの対戦結果（勝率）が履歴とグラフに載る

## 5. 技術選定
- 言語：Rust（安定版）。理由：速度はC++と同等で、メモリ破壊系のバグをコンパイル時に防げるため、無人開発に向く
- 計測：同じCIジョブ内で新旧を交互に複数回実行し、中央値で比較（共有ランナーのブレ対策）。読んだ局面数も併記
- CI：GitHub Actions（公開リポジトリの標準ランナーは無料。1ジョブ最大6時間）
- グラフ：GitHub Pages（静的ページ。CSVを読み込んで描画）
- 夜間実装：Claudeの定期実行（クラウド）。追加でCodex（PCのアプリ、PC起動時のみ）

## 6. 持ち主の判断が必要なこと
- Edaxとの対戦（M6）：EdaxはGPLライセンスの公開エンジン。コードは取り込まず、別プログラムとして対戦させるだけなら問題ないと判断している。止めたい場合は言ってもらう
- Codexの追加：PCで夜間にCodexアプリを動かすかどうか（M4以降、任意）
- 一晩の試行数：最初の1週間は1件。枠の減り方を見て2〜3件に増やすか決める
