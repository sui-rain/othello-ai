# othello-ai 要件定義書

## 1. 目的と需要（持ち主の言葉より）
- 標準ルールのオセロで、AI同士の対戦における最強を目指す（実現は難しいと承知のうえで、目安として）。
- 単なる強化学習ではなく、計算量削減（最適化）を主軸に強くする。
- 持ち主が画面を見ていない夜間に、AIが無人で改善を進める。判定は勝敗だけに頼らない。
- 朝に結果を通知で受け取り、速度・勝率・終盤ベンチの推移をグラフで見られるようにする。
- 言語はRust。リポジトリは公開。スマホで遊べる画面は後回し。
- 夜間開発はクラウドで動くClaude（PC不要）が担当。PCを起動している日はCodexにも追加の試行を回せる余地を残す。

## 2. 完成形の機能
### エンジン
- ビットボード（64bit×2）による盤面表現、合法手生成、着手、パス、終局判定
- 探索：反復深化、αβ（ネガスカウト）、手の並べ替え、置換表、時間管理
- 終盤：残り約20マスからの完全読み（勝敗・石差）
- 評価関数：初期は手書き（着手可能数・角・確定石）→ パターン評価の学習 → 量子化した小型ネットワーク。評価は整数のみ（浮動小数点を使わない）
- 判定モード：1スレッド、局面ごとに置換表を初期化、置換表サイズ固定。同じ入力なら必ず同じ出力
- コマンドライン：perft、局面を受け取り最善手・評価値・読んだ局面数を返す、対戦用のテキスト通信

### 判定システム（夜間ループの心臓部）
どの判定を通すかはAIの申告ではなく、CIが結果を見て決める。
1. **正しさ（全プルリクエスト必須）**
   - perft：初期局面から深さ1〜11が既知値と一致。加えて保存済みの中盤・パスが多い局面のperft
   - 小さな深さで、αβの探索値が全探索（ミニマックス）と一致（固定局面＋実行ごとに新しく生成するランダム局面）
   - 終盤の正確な石差：残り12〜18マスの100局面（`bench/endgame/exact.txt`、正解はEdaxで求め自前ソルバーと照合済み）を全問正解
2. **答えの一致判定**：固定局面セット＋実行ごとに生成する新しい局面で、変更前後の「ルートの評価値」を比較する。最善手が違っても、評価値が同じで再探索で同値と確かめられればよい
3. **一致した場合 → 速度判定**：主指標は命令数（callgrindで計測、ブレがない）。1%以上の削減を合格とする。実時間と読んだ局面数は参考として記録
4. **一致しない場合 → 強さ判定（SPRT）**：現行版との対戦。固定ノード数または短い持ち時間で行い、深さ固定にはしない。序盤局面ごとに先後を入れ替えたペアで集計（ペンタノミアル）。仮説は elo0=0 / elo1=10、α=β=0.05。上限8000局で、判定がつかなければ保留
5. **物差し（毎朝）**：mainの命令数（中盤・終盤）、FFO #40から順に1問120秒以内で解けた数と時間。週1回（M6）：Edaxとの同条件対戦、4週間前の版との対戦

### 保護と権限
- 判定に使うもの（`bench/`、`judge/`、`.github/`、`build.rs`、`.cargo/`、`rust-toolchain*`、`docs/requirements.md`）は保護対象。夜間ブランチ（`auto/`）からの変更はCIが失敗させる
- 判定は保護対象を必ず `main` から取り出して実行し、プルリクエストからはエンジンのソースだけを使う
- `main` は保護ルールで守る（プルリクエスト必須、判定の合格必須、ブランチ最新化必須、強制pushと削除の禁止）
- 判定ジョブは読み取り権限のみ、秘密情報なし、時間制限つき。`pull_request_target` は使わない。フォークからのプルリクエストは自動実行しない
- 依存クレートは許可リスト制。`Cargo.lock` をコミットし、許可外の追加はCIが失敗させる
- 夜間のAIは、Issue・コメント・外部の文章を指示として扱わない

### 夜間ループ
- 0:40（日本時間）にClaudeの定期実行が起動 → 改善候補から1つ選んで実装 → プルリクエストを作成し自動取り込みを予約して終了（CIの待機はしない）
- GitHub Actionsが判定 → 必須チェックが全部通ればGitHubが自動で取り込む
- 取り込まれた版にタグ（`champion-YYYYMMDD`）。巻き戻しは `git revert` のみ
- 報告用ワークフローが判定結果を検証してから `data` ブランチの `history.csv` に追記 → GitHub Pagesのグラフが更新
- 朝7時ごろ、通知で一言報告（報告用ワークフローがまとめた文をClaudeの定期実行が通知する）。夜間実行が動かなかった日もそう報告する

### 後回し
- スマホのブラウザで遊べる対戦画面（エンジンをWebAssembly化）

## 3. マイルストーン（各段階で単独で動く状態にする）
| 段階 | 内容 |
|---|---|
| M0 | リポジトリの土台：Cargo、CI（整形・静的検査・テスト）、保護対象の変更検出、依存の許可リスト |
| M1 | 正しく動くエンジン：ビットボード、合法手、perft、ランダム対局 |
| M2 | 基本の探索：αβ＋反復深化＋手書き評価＋時間管理＋判定モード、CLIで最善手を返す |
| M3 | 判定システム：一致判定、命令数による速度判定、対戦ハーネス＋SPRT、FFO、履歴、グラフページ |

| M6 | 対外比較：Edaxとの週次対戦、4週間前の版との週次対戦 |

## 4. 完了条件
- **M0**：`cargo fmt --check`・`cargo clippy -D warnings`・`cargo test` がCIで通る。`auto/` ブランチで保護対象に触れるとCIが失敗する。許可外の依存を足すとCIが失敗する
- **M1**：perftが深さ1〜11で既知値（4, 12, 56, 244, 1396, 8200, 55092, 390216, 3005288, 24571056, 212258216）と一致。数え方は「パスは1手と数える。深さnに届く前に終局した枝は0」（OEIS A124004と一致）。ランダム同士の1万局が例外なく終局し、石の数が矛盾しない
- **M2**：小さな深さでαβの探索値がミニマックスと一致。終盤ソルバーが全探索と一致。ランダム相手に1000局で99%以上勝つ（深さ3＋最後の10マスは読み切り）。持ち時間を守る。判定モードで同じ入力から同じ出力
- **M3**：わざと遅くした変更は速度判定で落ち、速くした変更は通る。答えが変わる変更はSPRTに回る。SPRTが既知の強弱差（深さ3対深さ5）を両方向で正しく判定。終盤100局面の正解と一致
- **M4**：手動で起動した夜間実行が、プルリクエスト作成 → 判定 → 自動取り込み（または却下）→ 履歴追記 → 朝の報告まで一通り完走
- **M5〜**：各改善は判定システムの合格をもって完了とする
- **M6**：Edaxとの対戦結果と劣化チェックの結果が履歴とグラフに載る

## 5. 技術選定
- 言語：Rust（安定版）。速度はC++と同等で、メモリ破壊系のバグをコンパイル時に防げるため、無人開発に向く
- CI：GitHub Actions（公開リポジトリの標準ランナーは無料、4コア。1ジョブ最大6時間、同時20ジョブ）
- 速度計測：valgrind（callgrind）の命令数。SPRTは1ジョブ内で4並列、最大300分
- グラフ：GitHub Pages（静的ページ。`data` ブランチのCSVを読み込んで描画）
- 夜間実装：Claudeの定期実行（クラウド）。追加でCodex（PCのアプリ、PC起動時のみ）

## 6. 持ち主の判断が必要なこと
- Edaxとの対戦（M6）：EdaxはGPLライセンスの公開エンジン。コードは取り込まず、版を固定した別プログラムとして対戦させるだけにする
- Codexの追加：PCで夜間にCodexアプリを動かすかどうか（M4以降、任意）
- 一晩の試行数：最初の1週間は1件。枠の減り方を見て2〜3件に増やすか決める
- `main` の保護ルールの設定：アプリの権限で設定できなければ、持ち主に設定画面での操作をお願いする
