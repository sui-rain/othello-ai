# 決めたことと理由

| # | 決めたこと | 理由 |
|---|---|---|
| D1 | 改善の判定を「正しさ」「速度（答え一致）」「強さ（SPRT）」の3段に分ける | 勝敗だけだと運に左右され、一晩で白黒がつかない。答えが変わらない変更は運なしで判定できる |
| D2 | 判定用データと採点スクリプトは `bench/` と `judge/` に置き、夜間のAIは変更禁止（CIで検出） | テストを緩めて「改善した」ことにする抜け道を防ぐ |
| D3 | 速度は同じジョブ内で新旧を交互に5回ずつ測り、中央値で3%以上の短縮を合格とする | 共有ランナーは実行ごとに速度が数%ぶれるため |
| D4 | SPRTは「+5 Elo以上強い」vs「強くない」の仮説、α=β=0.05、最大4000局で打ち切り | Stockfishの開発で使われる一般的な設定に近い。打ち切り時は保留扱い |
| D5 | 対局の序盤は、序盤8手のランダムな局面集から先後入れ替えで開始 | 同じ展開ばかりになるのを防ぎ、先手有利の偏りを打ち消す |
| D6 | 夜間の定期実行は0:40（日本時間）、一晩1件から開始 | 21:30開始の5時間枠の残りを使う。枠の消費量を1週間見てから増やす |
| D7 | 夜間のClaudeはCIの結果が出るまで待ち、取り込みと通知までを1回の実行で行う | 通知を1回にまとめ、朝の時点で結果が確定している状態にする |
| D8 | `main` への直接pushは禁止。取り込みは判定合格したプルリクエストのみ | 壊れた変更が最強版を上書きしないようにする |
| D9 | 評価関数は手書き → パターン学習 → 量子化ネットワークの順 | 計算量削減を主軸にする方針。学習は判定システムが整ってから |
| D10 | グラフページはGitHub Pages（静的） | 更新にAIを使わないので枠を消費しない |
